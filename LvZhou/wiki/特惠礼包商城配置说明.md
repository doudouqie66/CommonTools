# 特惠礼包商城配置说明

## 功能概述

特惠礼包模板是在原有「礼包模板」基础上新增的扩展功能，主要增加了**游戏外售卖、游戏内发货**的能力。开发者可以将礼包商品上架到绿洲工坊大厅的特惠礼包页面，玩家在游戏外即可浏览和购买，购买后通过邮件系统在游戏内领取。

> **相关链接**：礼包模板基础功能请参考 [礼包模板](https://developer.gp.qq.com/wikieditor/#/catalog/20143)

### 适用场景

- 玩家在绿洲工坊大厅（游戏外）浏览并购买礼包
- 购买后通过邮件接口在游戏内下发物品
- 支持固定礼包、随机礼包、自选礼包三种类型

### 商品类型说明

开发者在配置商品时，需要选择合适的商品类型：

| 商品类型 | 说明 | 适用范围 |
|----------|------|----------|
| 类型1 | 游戏内售卖 | 仅游戏内生效 |
| 类型2 | 绿洲大厅售卖 | 仅绿洲工坊大厅生效 |
| 类型3 | 两边都生效 | 工坊大厅 + 游戏内均生效 |

> **注意**：特惠礼包功能需要配置商品类型为**类型3**。原有类型1的礼包商品也可以改为类型3，但需要在版本更新时披露调整内容并进行测试。

## 功能发货流程

特惠礼包从配置到最终玩家领取，涉及编辑器、Cook平台、管理平台和游戏后台四个环节，整体流程如下：

![image_1.png](https://cgugc-video-test-1258633575.cos.ap-shanghai.myqcloud.com/wiki_picture/kdULlimage_1.png)

整体流程说明：

1. **编辑器**：配置物品表、礼包表、商品表，将礼包包装为商品后上传至Cook平台
2. **Cook平台**：导出玩法商品和礼包配置信息
3. **管理平台**：展示商品和礼包信息，开发者配置礼包上下架，管理员审核后上线
4. **游戏后台**：处理购买请求，通过邮件系统向玩家发送待领取邮件，玩家在游戏内邮件中心领取

> **特别说明**：StoreId=1 为玩法内售卖，StoreId=2 为大厅补给站售卖（差异化存档），StoreId=3 为礼包专用售卖（邮件流程）。特惠礼包走的是 StoreId=3 的邮件下发流程。

- **购买条件**：如下载最新版本、游玩时间达到要求等
- **购买限制**：如每周限购次数、剩余可购次数等

## 特惠礼包商城 - 编辑器配置

### 商品配置

> 更多商品配置说明见Wiki：[商业化系统——商品表（UGCShop）](https://developer.gp.qq.com/wikieditor/#/catalog/20008?autoJump=%E5%95%86%E5%93%81%E8%A1%A8%EF%BC%88UGCShop%EF%BC%89)

在编辑器的商品配置中，需要完成以下设置：

![image_4.png](https://cgugc-video-test-1258633575.cos.ap-shanghai.myqcloud.com/wiki_picture/IzK31image_4.png)

1. **商城ID**：选择 `两边都售卖` 后，该类礼包方可在绿洲工坊大厅-特惠礼包页面进行展示。当前版本中，两边都售卖仅对**礼包类型商品**生效
2. **商品排序**：影响封面显示的内容。排序值最大的排在最前，默认第一位是礼包封面内容。建议将高折扣、高吸引力的礼包排序设为最高

商品表中的核心配置项：

| 配置项 | 说明 |
|--------|------|
| 商品ID | 商品的唯一标识 |
| 商品类型 | 选择类型3（两边都生效） |
| 商品名称 | 商品的显示名称 |
| 物品ID | 关联的礼包物品ID |
| 是否售卖 | `永久售卖` 或 `限时售卖` |
| 货币类型 | 如 `绿洲币` |
| 售卖价格 | 商品的售卖价格 |
| 限购类型 | `不限购` / `每周限购` / `永久限购` |
| 限购数量 | 对应限购类型下的可购买次数 |
| 商城ID | 选择 `两边都售卖` |
| 商品排序 | 排序值，数值越大越靠前 |
| 折扣 | 折扣信息，如 `7折` |
| 折扣开始/结束时间 | 折扣生效的时间范围 |

### 礼包配置规范

#### 礼包类型

| 类型 | 说明 | 配置要求 |
|------|------|----------|
| 固定礼包 | 玩家获得礼包中的全部物品 | 明确列出所有物品及数量 |
| 随机礼包 | 按概率随机获得物品 | 需在描述中阐述清楚随机概率和数量范围 |
| 自选礼包 | 玩家从可选物品中选择 | 需在描述中说明自选内容范围 |

> **⚠️ 重要提示**：针对随机/自选礼包，必须在礼包物品描述上阐述清楚随机概率、数量范围、自选内容，避免给玩家造成错误引导。如有玩家投诉购买显示和获得物品不一致的行为，将面临游戏下架的风险。

#### 礼包封面与 icon 设计规范

礼包封面和商品icon虽与游戏内icon一致，但建议开发者在设计时注意以下几点：

- **图片清晰**：保证图片分辨率，避免模糊
- **物资明确**：让玩家一眼就能识别礼包内容
- **品质色区分**：使用不同的品质色边框区分物品稀有度

> 所有绿洲工坊的玩法礼包会集合在特惠礼包页面，清晰、精美的设计图片会更加吸引玩家关注游戏并购买礼包商品。

## 邮件接口下发商品

> **⚠️ 此步骤为必选项，未接入将导致商品无法正常下发。**

### 接入说明

接入礼包上架大厅特惠礼包页后，需要开发者接入邮件模板，或者通过邮件API自行实现邮件相关功能，确保玩家在游戏外购买的礼包能够通过邮件系统在游戏内正常下发。

### 未接入的风险

如未接入邮件模板，上架的商品将无法正常下发，开发者需承担以下风险：

- 用户退款
- 游戏临时下架整改

> **邮件模板参考**：请参考[邮件模板Wiki文档](https://developer.gp.qq.com/wikieditor/#/catalog/20393)进行接入配置。

## 常见问题

**Q: 原有类型1的礼包商品能否直接改为类型3？**
A: 可以修改，但需要在版本更新时披露调整内容并进行测试，确保功能正常。

**Q: 礼包排序规则是什么？**
A: 排序值最大的排在最前，默认第一位是礼包封面内容。建议将高折扣、高吸引力的礼包排序设为最高。

**Q: 玩家在游戏外购买的礼包如何领取？**
A: 购买后系统会通过邮件系统向玩家发送待领取邮件，玩家需要进入游戏内的邮件中心领取。因此开发者必须接入邮件模板。
