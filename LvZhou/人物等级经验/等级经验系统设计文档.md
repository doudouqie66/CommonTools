# 等级经验值系统 - Douluo 项目适配文档

> 项目：和平精英绿洲启元 UGC / Douluo  
> 更新日期：2026-07-15  
> 状态：准备开始接入 Lua 逻辑

---

## 一、当前项目结论

本系统不再按通用模板从零创建。Douluo 项目里等级经验数据表已经存在，当前要做的是把 Lua 逻辑接入现有的玩家状态、属性刷新、任务系统。

### 已存在资源

| 资源 | 路径 | 当前状态 |
|---|---|---|
| 等级配置表 | `Asset/Data/Table/Lin/DT_PlayerLevelConfig.csv` / `.uasset` | 已有 1-40 级 |
| 波次经验表 | `Asset/Data/Table/Lin/DT_WaveExpConfig.csv` / `.uasset` | 已有 1-40 波 |
| 玩家长期属性 | `Script/Blueprint/UGCPlayerState.lua` | 已有 `BaseAttack` / `BaseMaxHp` |
| 属性刷新链路 | `Script/Blueprint/UGCPlayerPawn.lua` | `RefreshStateMgrProperty` 会刷新血量、攻击和客户端显示 |
| 客户端属性同步 RPC | `Script/Blueprint/UGCPlayerController.lua` | 已有 `Client_RefreshProperty`、`Server_SetFinalAttack`、`Server_SetFinalMaxHp` |
| 任务进度入口 | `Script/Lin/TaskMgr.lua` | 目前主要支持每日/每周活跃任务 |

### 重要适配原则

升级属性不要直接用 `UGCAttributeSystem.SetGameAttributeValue` 写死到 Pawn 上。

Douluo 现有角色成长已经以 `UGCPlayerState.BaseAttack` / `UGCPlayerState.BaseMaxHp` 作为长期基础属性来源，魂环和固定属性增长也走这条链。等级升级应该复用这条路径：

```
PlayerLevelSystem.AddExp
    -> 计算新等级
    -> 计算本次升级需要增加的 AttackBonus / HealthMaxBonus 差值
    -> 写入 PlayerState.BaseAttack / PlayerState.BaseMaxHp
    -> Pawn:RefreshStateMgrProperty(true)
    -> Client_RefreshProperty 更新 UI / StateMgr
```

这样可以避免等级系统和魂环、武器、境界、死亡重生恢复链路互相覆盖。

## 二、数据表定义

### DT_PlayerLevelConfig

路径：`Asset/Data/Table/Lin/DT_PlayerLevelConfig`

| 字段 | 类型 | 说明 |
|---|---|---|
| Level | int32 | 玩家等级，1-40 |
| ExpRequired | int32 | 到达该等级需要的累计经验 |
| HealthMaxBonus | int32 | 该等级提供的生命加成 |
| AttackBonus | int32 | 该等级提供的攻击加成 |

当前表已经配置到 40 级，`ExpRequired` 是累计值。Lv1 为 0，Lv40 为 78000。

### DT_WaveExpConfig

路径：`Asset/Data/Table/Lin/DT_WaveExpConfig`

| 字段 | 类型 | 说明 |
|---|---|---|
| WaveID | int32 | 波次/关卡 ID，1-40 |
| KillExp | int32 | 当前波次怪物击杀经验 |

当前表已经配置到 40 波。前期每只怪 2 点经验，后期逐步提升到 30 点。

## 三、PlayerState 字段设计

等级经验应该放在 `Script/Blueprint/UGCPlayerState.lua`，原因：

- 当前项目注释已经说明 PlayerState 用于角色状态和重连恢复。
- `ARCHIVE_KEYS` 已经集中管理跨局存档。
- `GetReplicatedProperties` 已经集中管理客户端可读状态。
- `BaseAttack` / `BaseMaxHp` 已经在这里持久化。

### 新增字段

```lua
PlayerLevel = 1, -- 玩家等级
PlayerExp = 0, -- 当前累计经验
PlayerMaxExp = 100 -- 下一级累计经验阈值，满级后等于当前经验
```

### 存档注册

加入 `ARCHIVE_KEYS`：

```lua
{
    key = "PlayerLevel",
    field = "PlayerLevel",
    default = 1
}, {
    key = "PlayerExp",
    field = "PlayerExp",
    default = 0
}, {
    key = "PlayerMaxExp",
    field = "PlayerMaxExp",
    default = 100
}
```

### 复制属性

加入 `GetReplicatedProperties()`：

```lua
"PlayerLevel", "PlayerExp", "PlayerMaxExp"
```

### 读写函数

保持当前文件风格，新增简单 getter/setter：

```lua
function UGCPlayerState:GetPlayerLevel()
    return self.PlayerLevel
end

function UGCPlayerState:SetPlayerLevel(value)
    self.PlayerLevel = tonumber(value) or 1
    self:SaveToArchive()
end

function UGCPlayerState:GetPlayerExp()
    return self.PlayerExp
end

function UGCPlayerState:SetPlayerExp(value)
    self.PlayerExp = tonumber(value) or 0
    self:SaveToArchive()
end

function UGCPlayerState:GetPlayerMaxExp()
    return self.PlayerMaxExp
end

function UGCPlayerState:SetPlayerMaxExp(value)
    self.PlayerMaxExp = tonumber(value) or 100
    self:SaveToArchive()
end
```

## 四、PlayerLevelSystem 设计

新增文件：

`Script/Common/PlayerLevelSystem.lua`

### 职责

`PlayerLevelSystem` 只负责等级经验规则，不直接管理 UI，不直接写任务组件。

主要函数：

| 函数 | 作用 |
|---|---|
| `LoadConfig()` | 读取等级表和波次经验表 |
| `GetLevelByExp(totalExp)` | 按累计经验换算等级 |
| `GetLevelConfig(level)` | 获取指定等级配置 |
| `GetWaveKillExp(waveID)` | 获取指定波次击杀经验 |
| `AddExp(PlayerController, amount)` | 服务端给玩家增加经验 |
| `ApplyLevelBonus(PlayerController, oldLevel, newLevel)` | 升级时写入基础属性差值 |

### AddExp 流程

```lua
PlayerLevelSystem.AddExp(PlayerController, amount)
    -> 从 PlayerController.PlayerState 读取 PlayerLevel / PlayerExp
    -> newExp = oldExp + amount
    -> newLevel = GetLevelByExp(newExp)
    -> 如果升级，ApplyLevelBonus(PlayerController, oldLevel, newLevel)
    -> 写回 PlayerState.PlayerLevel / PlayerExp / PlayerMaxExp
    -> UnrealNetwork.RepLazyProperty(PlayerState, "PlayerLevel")
    -> UnrealNetwork.RepLazyProperty(PlayerState, "PlayerExp")
    -> UnrealNetwork.RepLazyProperty(PlayerState, "PlayerMaxExp")
```

### ApplyLevelBonus 规则

为了避免重复叠加，升级时只加“旧等级之后到新等级之间”的差值。

例如 Lv1 升到 Lv3，只累计 Lv2、Lv3 的配置：

```lua
local addHp = 0
local addAttack = 0
for lv = oldLevel + 1, newLevel do
    local cfg = PlayerLevelSystem.GetLevelConfig(lv)
    addHp = addHp + (tonumber(cfg.HealthMaxBonus) or 0)
    addAttack = addAttack + (tonumber(cfg.AttackBonus) or 0)
end
```

然后写入现有长期属性：

```lua
local playerState = PlayerController.PlayerState
playerState:SetBaseAttack(playerState:GetBaseAttack() + addAttack)
playerState:SetBaseMaxHp(playerState:GetBaseMaxHp() + addHp)

local pawn = PlayerController.Pawn or PlayerController:K2_GetPawn()
if pawn and pawn.RefreshStateMgrProperty then
    pawn:RefreshStateMgrProperty(true)
end
```

## 五、经验来源接入

### 第一阶段：测试入口

先在 `UGCPlayerController.lua` 增加一个服务端测试入口，方便 UI 或控制台触发：

```lua
Server_AddPlayerExp
```

并加入 `GetAvailableServerRPCs()` 白名单。这个入口只用于测试和后续 UI 按钮，不作为最终怪物经验来源。

### 第二阶段：怪物击杀经验

当前怪物脚本分散在多个目录，例如：

- `Script/Blueprint/Prefabs/Monsters/MainScene/.../BaseMons.lua`
- `Script/Blueprint/Prefabs/Monsters/Dungeon/Boss_*.lua`
- `Script/Blueprint/Prefabs/Monsters/TowerMonster/Tower_Mons_1.lua`

这些脚本现在已经在击杀时调用：

```lua
TaskMgr:RequestAddTaskProgress(L_Enum.AllTask.KillMonster, 1)
```

后续可以在怪物死亡/奖励位置增加经验逻辑。为了减少大面积重复修改，优先找共享父类或通用死亡函数；如果确实没有共享入口，再逐类补。

### 第三阶段：TaskMgr 任务线

任务管理笔记里提到 `LevelExperience`：

```lua
TaskDef.TaskLine.LevelExperience = "人物等级经验"
```

但当前 `Script/Lin/TaskMgr.lua` 主要按 `EveryDay` / `EveryWeek` 活跃任务更新进度，还没有完整成长任务线封装。

建议等级系统本体先独立完成。确认等级、经验、属性刷新正常后，再接入 `LevelExperience` 成长任务线。

## 六、推荐实施顺序

1. 修改 `UGCPlayerState.lua`
   - 增加 `PlayerLevel` / `PlayerExp` / `PlayerMaxExp`
   - 加入 `ARCHIVE_KEYS`
   - 加入 `GetReplicatedProperties`
   - 增加 getter/setter

2. 新建 `Script/Common/PlayerLevelSystem.lua`
   - 读取 `DT_PlayerLevelConfig`
   - 读取 `DT_WaveExpConfig`
   - 实现经验、升级、属性加成

3. 修改 `UGCPlayerController.lua`
   - `UGCRequire("Script.Common.PlayerLevelSystem")`
   - 增加 `Server_AddPlayerExp`
   - 加入 RPC 白名单

4. 本地测试
   - 给自己加 100 经验，确认 Lv1 -> Lv2
   - 检查 `PlayerState.PlayerLevel / PlayerExp / PlayerMaxExp`
   - 检查 `BaseAttack / BaseMaxHp` 是否增加
   - 检查重生后属性是否保持

5. 再接怪物击杀经验
   - 优先找共享死亡逻辑
   - 根据当前波次读取 `DT_WaveExpConfig`
   - 不确定当前波次来源时，先用固定测试值，不要硬猜

6. 最后接 TaskMgr 成长任务线
   - 明确 `LevelExperience` 是成长型还是活跃型
   - 补 `TaskDef` / 数据资产配置
   - 在升级成功时更新任务线进度

---

## 七、暂不处理

以下内容不放在第一阶段：

- 等级经验 UI 进度条
- 升级特效和广播
- 死亡掉经验
- 满级经验转换货币
- 经验倍率活动
- TaskMgr 成长任务线完整配置

第一阶段目标只有一个：服务端加经验后，玩家能升级，经验能保存/同步，基础攻击和血量能沿当前项目链路正确刷新。
