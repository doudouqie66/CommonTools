# 活动模板

UGC活动模板是和平精英绿洲起源编辑器提供的官方活动系统，允许创作者快速配置和管理游戏内的活动任务和签到功能，无需编写复杂的代码即可实现完整的活动逻辑。

活动模版当前支持配置两种活动类型：【任务型活动】和【签到型活动】。

活动标题、副标题、活动背景图、任务类型、任务奖励、任务重置类型、签到天数、是否支持补签、签到奖励等均在编辑器表格内配置，活动开始时间、活动结束时间在管理端配置。


<br>

## 功能概述

活动模板系统通过配置驱动的方式，为UGC工程提供任务型和签到型两种标准活动类型。系统由三个核心模块组成：配置层（数据表格）、逻辑层（ActivityManager）、表现层（UI组件）。创作者只需在编辑器中配置相关表格和UI资源，系统会自动处理任务进度跟踪、奖励发放、签到状态管理等功能。

## 模板结构

活动模板

![image.png](https://cgugc-video-test-1258633575.cos.ap-shanghai.myqcloud.com/wiki_picture/B8ESyimage.png)

**A. 自定义活动页签名称**

支持配置多种活动，不同活动通过页签的方式进行切换

- 编辑器可设定：活动页签名称
- 标题字数限制：显示上限为7个字
- 页签数量显示：显示上限为10个页签

**B. 自定义活动背景图**

编辑器可配置背景图，不配则展示默认背景图（蓝色纯色背景+光子鸡）

**C. 任务区域**

编辑器勾选了任务型活动后，显示任务区域

任务的数量上限为4个

![image.png](https://cgugc-video-test-1258633575.cos.ap-shanghai.myqcloud.com/wiki_picture/IFaKfimage.png)

C1. 任务重置类型

开发者可通过编辑器内配置，显示任务的重置类型，有4种重置类型，“常驻”、“每日”、“每周”、“每月”

C2. 任务文案

开发者可通过编辑器内配置，显示任务文案，显示上限为37个中文字符，超出字数上限部分显示“...”

C3. 任务进度

开发者可通过编辑器内配置，显示任务进度。例如在线4分钟任务，则进度显示为“0/4”

C4. 任务奖励

开发者可通过编辑器内配置，显示任务奖励，显示上限为2个奖励道具

**D. 活动时间**
开发者可以根据管理端配置，显示活动的开启时间、结束时间。设定时间后，活动里的任务、签到的开始、结束时间会同步变更为该活动的开始、结束时间。
- 时间设定规则：结束时间必须晚于开始时间
- 永久开启：在管理端选择永久开启，则活动立刻开启，且没有结束时间
- 注意事项：PIE里的活动均为永久开启

**E. 活动说明**

根据编辑器内配置，显示活动说明内容，显示上限为132个中文字符，超出字数上限部分不做显示


**F. 活动标题**

根据编辑器内配置，显示活动标题，显示上限为7个中文字符，超出字数上限部分显示“...”

**G. 活动副标题**

根据编辑器内配置，显示活动副标题，显示上限为19个中文字符，超出字数上限部分显示“...”

**H. 签到区域**

编辑器勾选了签到型活动后，显示签到区域

![image.png](https://cgugc-video-test-1258633575.cos.ap-shanghai.myqcloud.com/wiki_picture/BsNtIimage.png)

- 每个排名区间最多可以配置5种奖励
- 对于非重置型榜单，玩家可领取奖励的时间为榜单的 **结算时间** 至 **结束时间** 之间，逾期无法补领
- 对于重置型榜单，玩家通过 ``历史榜单数据`` 界面领取奖励，且根据重置类型历史榜单将额外保留展示一天/一周/一个月

H1. 签到天数

签到活动的天数，签到天数上限为7天

H2. 签到奖励

每日签到获得的奖励道具，奖励数量上限为1个道具

H3. 签到及补签规则（和签到模版规则一致）

H3.1-签到规则

领奖为累签领奖方式，与自然日期无对应关系，按排列顺序依次领奖，每天领取一次。若某日没有登录领奖，不会跳过，再登录时按上次领奖进度，继续领奖即可

H3.2-补签规则

1. 所有签到活动支持补签，允许补签天数以及消耗道具支持表格配置
2. 若触发补签，则在本日应该签到的奖励后，加上x天可补签的奖励并显示补签按钮，x取决与配置
3. 先签到后补签，补签位置永远在本日该签到奖励后，与天数无绑定关系，若玩家只签到不补签，则第二天可签到和补签奖励依次向后移动

H3.3-签到状态

【已签到】：已完成签到的天数显示该按钮
【签到】：可签到的天数显示该按钮
【待签到】：尚未签到且不能补签的天数，显示该按钮
【补签】：已签到后点击补签按钮，弹补签窗口，消耗对应道具进行补签；若未完成本日签到，点击补签按钮弹出提示文字 “本日签到后才能补签！”
【待补签】：完成上一个可补签日，才能补签下一个；若未完成可补签，点击【待补签】弹出提示文字“上一个补签日完成后才能补签！”

## 活动配置

活动模板的UI界面由以下几个核心区域组成：

|区域|说明|配置方式|
|-|-|-|
|页签区域|显示不同活动的切换页签|ActivityTable.TabName|

## 活动调试

### 日志调试

ActivityManager内置了完善的日志系统，包含【Log】、【Warning】、【Error】、【Fatal】四个级别，日志前缀为 ``[Activity][级别][函数名]`` ，方便定位问题，使用 ``log_tree`` 可以输出表格结构数据。

<br> 

### GM调试

为便于进行功能调试，开发者可通过配置通用GM面板，添加一个打开通行证界面的快捷入口，具体配置方法请参阅 [扩展GM功能](https://developer.gp.qq.com/wikieditor/#/catalog/20109?autoJump=%E6%89%A9%E5%B1%95GM%E5%8A%9F%E8%83%BD) 。

使用配置的GM指令快速打开活动界面,在PIE中可以直接测试活动功能,PIE中的活动均为永久开启，不受时间限制。

``` Lua
local ProjGM = {}
local FreezeExpSwitch = false

function ProjGM:Register(DebugUI)
    local UGCGMUI = require("client.ingame.ugc.ugc_gmui")

    local CurFuncList = {}
    CurFuncList["调试"] = {
        ["活动"] = {
            {UGCGMUI.ItemTypeEnum.Button, {{"打开活动主界面"}}, "C_OpenActivityMainUI"},
        },
    }

    return CurFuncList
end

function ProjGM:C_OpenActivityMainUI()
    print("C_OpenActivityMainUI")
    if ActivityManager then
        ActivityManager:OpenMainUI()
    end
end

return ProjGM
```

进行调试期间，从通用GM面板中打开通行证界面，即可查看活动的展示与操作效果。
